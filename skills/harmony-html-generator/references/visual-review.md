# 视觉验收

仅在静态校验通过后的质量模式中读取本文件。检查当前请求，不与通用展示页或页面模板比较。

## 验收顺序

1. 以 390×844 渲染用户请求的主题；用户明确要求双主题时分别渲染。
2. 用一句话复述页面唯一目的，确认首屏支持该目的。
3. 先看整个屏幕的阅读顺序和视觉重量，再检查单个组件。
4. 检查几何、裁切、滚动、触控区域和本地资源。
5. 检查字体、色彩、圆角、间距和表面是否遵守统一决策。
6. 检查平台资产、交互状态、无障碍和需求一致性。
7. 只做一轮聚焦修复，然后重新渲染并再次静态校验。

## 硬失败

- 出现横向滚动、可见重叠、意外裁切或文本跑出所属表面；
- 关键内容或操作被固定区域遮挡；
- 本地图片、字体或图标缺失，或 Symbol 出现 tofu 方框；
- 主文字、操作或状态的对比度明显不足；
- 页面出现一个以上争抢注意力的主要操作；
- 交互控件没有清楚可见的命中区域或焦点反馈；
- 原生控件明显未应用运行时样式；
- 主题切换后语义关系丢失，或深色模式只是整页反色；
- 页面高度造成大面积无意义空白；
- 用户要求的信息缺失，或出现用户未要求的功能。

## 评分维度

每项按 `通过 / 需修复 / 不适用` 判断；存在任何硬失败时不得宣称完成视觉验收。

### 目的与层级

- 第一、第二、第三阅读目标是否一眼可辨？
- 最重要内容是否靠位置、尺度和留白获得优先级，而不是靠装饰堆叠？
- 标题、正文、说明的字号和字重是否与信息价值一致？
- 删除颜色后，阅读顺序是否仍成立？

### 分组与间距

- 概念分组之间的距离是否明显大于组内距离？
- 24 / 12 / 8 / 4 的节奏是否稳定，边缘是否对齐？
- 同一组件家族是否保持一致 padding？
- 是否存在无法解释的一次性间距？

### 构图与密度

- 390px 画布上的视觉重量是否平衡？
- 重复信息是否规则、可扫描？
- 非对称是否表达真实优先级？
- 是否形成由同尺寸卡片组成的墙？
- 沉浸媒体是否真的来自用户内容，而不是装饰占位？

### 色彩、表面与材质

- 画布、普通表面、控件和真实浮层是否容易区分？
- 主蓝是否只强调主要操作、选择或核心信息？
- 状态色是否对应真实状态？
- 普通卡片是否避免不必要的整圈边框和阴影？
- 半透明与阴影是否只用于真实重叠的浮层，而不是整页玻璃拟态？

### 圆角与几何

- 相同类型的卡片和控件是否使用相同圆角？
- 连续列表是否避免逐行卡片化？
- 胶囊是否只用于确有语义的短标签或圆形操作？
- 图标、文字和控件是否在同一视觉基线上？

### 字体与文案

- 是否只使用 HarmonyOS Sans 与允许的三个字号角色？
- 正文是否舒适可读，元信息是否没有过小或过淡？
- 是否避免短标签异常换行、孤行和拥挤的元信息块？
- 文案是否具体、友好、尊重，没有占位文本、重复标题或模糊口号？

### 图标与控件

- 图标语义是否准确，体量和字重是否一致？
- 是否避免 Emoji、字符图标和多套图标风格混用？
- 按钮、输入、toggle、radio、checkbox 和 slider 是否具有明确状态？
- 可交互对象是否在按压或键盘焦点时提供克制反馈？

### 无障碍

- 图标按钮是否具有可访问名称？
- 输入控件是否具有名称，图片是否具有准确 `alt`？
- DOM、视觉和键盘焦点顺序是否一致？
- 状态是否不只依赖颜色表达？
- 减少动态偏好下是否仍保留必要反馈？

### 需求一致性

- 所有必要信息是否可见，或能通过自然滚动到达？
- 是否删除用户未要求的模块、操作和媒体？
- 是否使用真实领域文案，而不是为视觉效果发明产品功能？

## 修复优先级

按以下顺序修复：硬失败 → 目的与层级 → 溢出和几何 → 间距节奏 → 对比度与字体 → 平台细节。只修改最小相关子树或 class 列表，保留已经正确的数据属性、内容和结构。
